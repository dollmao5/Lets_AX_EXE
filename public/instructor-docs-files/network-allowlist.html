🛡️ 2. 추가 요청: SSL 검사(HTTPS 복호화) 예외 및 인증서 폐기 확인 (2026-08-06 · 2026-08-10 실측 보강)

🔎 증상 — 교육·운영 PC에서 브라우저는 위 사이트에 접속되지만, 프로그램 방식의 HTTPS 도구는 연결이 거부됩니다. 도구 계열에 따라 오류가 다릅니다:

  • Windows 표준 TLS(schannel) 계열 — curl 등: CRYPT_E_NO_REVOCATION_CHECK 오류
  • OpenSSL 계열 — Node.js 등: UNABLE_TO_VERIFY_LEAF_SIGNATURE 오류 (강사 Wrap-up 보드의 팀 요약 생성이 이 방식이라, 예외 처리 없이는 교육장에서 요약 생성이 실패합니다)

🧩 원인 (2026-08-06 실측 · 2026-08-10 보강) — 사내망 SSL 검사 장비가 HTTPS를 복호화한 뒤 사내 CA로 재서명하는데, 재발급 인증서에 세 가지 결함이 실측으로 확인되었습니다:

  1. 폐기 확인 정보(CRL 배포 지점·OCSP 주소) 누락 — Windows(schannel)는 폐기 여부를 확인하지 못하면 연결을 거부 (2026-08-06)
  2. 중간 인증서 체인 미전달 — 재서명된 서버 인증서만 전달되고 발급 CA 체인이 빠져 있어, OpenSSL 계열 도구가 신뢰 경로를 구성하지 못함 (2026-08-10)
  3. 사내 CA 키 강도 미달 — 사내 CA를 수동으로 신뢰시켜도 최신 TLS 라이브러리가 CA certificate key too weak로 거부 — 현행 보안 기준(RSA 2048bit·SHA-256 이상) 미달 (2026-08-10)

※ 2·3번은 예외 처리 대신 우회하려면 각 도구의 보안 기준을 인위적으로 낮춰야 하므로(보안상 부적절), 아래 1번 예외 목록 방식이 유일하게 안전한 해결책입니다.

📌 요청 (택 1)
  1. (권장) 위 표의 필수 도메인들을 SSL 검사(복호화) 예외 목록에 추가 — 원본 인증서가 그대로 전달되어 폐기 확인이 정상 동작하며, 파일 업로드 등 실습 기능 오작동 예방에도 도움이 됩니다.
  2. (대안) SSL 검사 장비가 재발급하는 인증서에 사내 CA의 CRL/OCSP 주소를 포함하도록 설정하고, 해당 사내 폐기 확인 서버로의 접근을 허용

📎 참고 — 1번 적용 시 함께 허용 필요한 공인 CA 폐기 확인 도메인 (OCSP/CRL은 HTTP 80 포트 사용이 일반적)
