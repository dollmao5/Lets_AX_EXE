> 이 문서는 클립 본문을 작성·수정할 때 용어와 표기를 통일하기 위한 기준 문서다.

> 파생 파일 신선도)과 어긋나면 배포 게이트에서 실패한다.

## 2) 프롬프트 배지 5종 (정의 정본)

실습 클립의 프롬프트 제목 앞에 붙는 `prompt-mode-badge`는 아래 5종만 사용한다.

| 배지 | 의미 |
|---|---|
| **대화형** | AI가 질문하면 답하면서 진행한다 |
| **복붙형** | 필요한 자료를 먼저 넣고 프롬프트를 한 번 붙여넣는다 |
| **이어서형** | 앞 단계와 **같은 ChatGPT 대화창**에 붙여넣는다 (새 대화를 열지 않음) |
| **설정형** | 새 채팅의 첫 메시지(역할 지침)로 붙여넣는다. 유료 플랜은 맞춤형 GPT의 지침 입력란에도 사용 가능 |
| **테스트형** | 같은 채팅에서 테스트 질문으로 동작을 확인한다 |

공통 실행 순서(본문 표준 문구): ① 배지와 지정 도구 확인 → ② 필요한 파일 먼저 첨부 →
③ 복사·붙여넣기 → ④ 대화형이면 AI 질문에 답변 → ⑤ 이어서형이면 새 대화를 열지 않음 →
⑥ 결과의 누락·오류·민감정보 확인 후 저장.

## 3) 산출물 명명 규칙

산출물의 단일 원장은 `content/axcamp/deliverables.json`이다 (현재 필수 8종 + 파일 외 형태
포함 13종). **본문에 산출물 파일명을 쓸 때는 반드시 원장과 글자 단위로 일치**해야 하며,
린트가 자동 검사한다.

명명 패턴:

```
CH{챕터번호}_{산출물명(언더스코어 구분)}_성명.md     예) CH03_우리팀_필요행동역량_성명.md
{조번호}조_{주제}_{형태}.{확장자}                    예) 1조_AI시대_리더역할_토론대화문.txt
```

- 개인 산출물은 `_성명` 접미사, 팀 산출물은 `N조_` 접두사를 쓴다.
- 산출물을 추가·개명할 때의 순서: ① `deliverables.json` 갱신 → ② 본문 수정 →
  ③ `npm run regen:clip -- <clipKey>` → ④ `npm run lint:content` 통과 확인.

## 4) 본문 수정 워크플로 (요약)

1. `content.html`만 수정한다 (`content.md`/`content.txt`/`metadata.json`은 파생 파일 — 직접 수정 금지).
2. `npm run regen:clip -- <clipKey>` (전체는 `--all`)로 파생 파일을 재생성한다.
3. `npm run lint:content`로 5종 검사(산출물 파일명 / 내비 href / 이미지 src / 금칙어 / 신선도)를 통과시킨다.
4. 로컬 4071 서버에서 렌더를 확인한다. 배포는 커밋·푸시(또는 루트 퍼블리시 버튼) → GitHub Actions가 린트 게이트 후 Pages에 배포.

## 5) 숨김·복구 규약 (요약)

콘텐츠를 화면에서 빼야 할 때 파일을 지우지 않는다. `public/app.js`의 블루프린트에서
주석 처리하고 `HIDDEN_CLIP_KEYS_REDIRECT_SET`에 키를 추가하며, `[HIDDEN]` 마커와
`복구` 주석을 남긴다. 자세한 규칙은 `CLAUDE.md`의 "Visibility is a rendering layer" 절 참조.
고아·중복 자산은 삭제 대신 `_archive/`로 이동하고 `_archive/README.md`에 기록한다.
